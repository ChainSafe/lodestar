Lodestar · src/fork_choice · PR #10564

Inputs write facts and mark changed votes; getHead derives the rest

Every handler writes a few flat arrays, sets dirty, and marks the validators whose vote changed. A vote is a 4-byte id into a table of distinct messages. Per-node vote totals persist in votes.vote_weight and move only for changed validators; viability, node status, best children and the head are rebuilt by head.zig compute on the first getHead after a change.

Layout

Rows are blocks, three node ids per row, and a parent is always an earlier row

Every scene below draws the same store panel at the same coordinates. Left: the call path, with the active function lit and its file:line. Right: each array as one strip of cells. A solid accent box marks a write at that step, a dashed box marks a read, and a dot runs from the writer to the cell.

Values are an example that the code would produce, not a recorded run. Weights are in ETH; the code stores Gwei. A vote cell holds a target id; the vote_targets strip turns the id into its message and node. A · cell is not shown in that scene, and a dashed empty cell does not exist yet.

Who writes

compute rebuilds head_cache; handlers only mark changed votes, and new balances and prune move vote_weight

R reads, W writes. The last two columns are the counted vote state that votes keeps between runs (vote_weight, applied_votes, changed_votes), and head_cache, which compute rebuilds. The last column says when the handler sets dirty. The queued_votes column includes queued_validators and queued_count, which change when an entry is set or cleared. "compact" means the target table compacted itself and renumbered every id list.

Block

A block passes the same checks up to three times, then becomes one new row in every column

Attestation

An attestation interns its target once, then writes a 4-byte id for each validator whose vote is newer
