# Native gossip queue rules

With the native backend, the lodestar-z gossip processor (`src/network/gossip_processor/`) owns gossip queueing: admission, per-kind limits, credits, grouping, dependency waiting, deadlines and slot eligibility. Lodestar supplies the named per-kind limits (`gossipKindLimits` in `config.ts`), the dependency answers and the validators (`executor.ts`), which are the same functions `NetworkProcessor` (`../../processor/`) runs.

Each rule below sits next to its `NetworkProcessor` counterpart on unstable, with a decision: **mirror** (same rule), **equivalent** (same bound or outcome by another mechanism), **intentionally different**, **not yet mirrored** (an open requirement), or **unsupported** (Gloas, which native refuses at startup). Each `NetworkProcessor` semantics change on unstable adds a row to the second table when the branch rebases.

The tables originated from a comparison of lodestar-z 39616cb2 and unstable fbb58f7280; the branch base is 92b9ec6e8b. They are a comparison inventory, not a claim of complete behavioral parity. The current pump lives in lodestar-z's `bindings/src/network-pump.js`, and `bindings/src/network-tickets.js` owns completion settlement. `nativeNetworkCore.ts` supplies the host callbacks; asynchronous validation and serving retain their obligations until completion.

## Runtime configuration and failures

Select native networking with `--network.backend=native --tcp=false --quic=true`. It supports IPv4, IPv6, or both, with at most one QUIC listener and one discovery listener per family. Discovery can learn advertised endpoints; explicit endpoints remain fixed. The workspace override links `@chainsafe/lodestar-z` to the adjacent `../lodestar-z-network-all` checkout because the network and LevelDB APIs are not yet published. Build that checkout’s mainnet binding before installing and running Lodestar.

When a peer store directory is configured, `rememberedPeers.ts` loads and periodically saves up to 256 qualified peers in `native-remembered-peers.json`, scoped to the genesis validators root and expiring after 24 hours. A missing or invalid file gives a cold start. Shutdown attempts a final snapshot before closing the network.

`NativeIntent` keeps one submitted update and one pending batch. Pending Status, custody and core-topic values coalesce to the latest request; committee demands merge. Callers in the same pending batch share its completion, so a superseded intermediate value need not be applied. Failed batches leave the last acknowledged state unchanged. The adapter submits only one state command at a time, using admission reserved from unrelated commands, without a retry timer. Once an admitted command races shutdown, rejection is not proof that its effect was rolled back.

Building or publishing an exchange result while JavaScript remains runnable is part of the bridge contract: a failure there is process-fatal, not an operation-local `NetworkResultAllocationFailed` rejection. If the JavaScript environment has stopped, native teardown reclaims the outstanding obligations.

## Rules

| Rule                          | Native                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | NetworkProcessor                                                                                                                                                                                                                                                             | Decision                                                                                                                                                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission and per-kind limits | Each kind has an item and a byte limit (`gossipKindLimits`). Bytes are 4 KiB pages, at least the kind's largest compressed message. One peer holds at most half of a kind's items, and about half of its bytes: the peer's byte share also counts inline storage and is never below the kind's largest message. A message without room is refused at receipt: no verdict, no forwarding, no score effect.                                                                                                                                    | One queue per topic type with a fixed length (blocks 1024, blobs and columns 4096, aggregates 5120, attestations 24576, others 1024 to 16384), counted in items.                                                                                                             | Intentionally different: bytes are bounded and preallocated, limits are sized to a slot's traffic, and each peer has a share.                                                                                                                  |
| Drop order when full          | Attestations, aggregates, sync messages and contributions evict the oldest message of the kind that is queued, awaiting a dependency check or waiting, with an Ignore verdict. Other kinds refuse the new message.                                                                                                                                                                                                                                                                                                                           | LIFO queues (aggregates, sync messages, contributions) drop their oldest message and FIFO queues their newest. The attestation queue drops the first message of its oldest indexed group, which need not be the oldest message left; awaiting messages are not in the queue. | Mirror for the other kinds. Intentionally different for attestations: native evicts the oldest attestation it holds, including one waiting on a dependency.                                                                                    |
| Byte and item credits         | A message holds its kind's item credit and its peer's share until it retires, and its kind's payload pages until it is delivered to the host. Host execution has separate per-kind item and byte credits, held from claim until the host's verdict and split from the host budget (4096 items and 64 MiB by default) by `executionItems` and `executionBytes`, capped by `maxGossipTopicConcurrency` and the processor items.                                                                                                                | Queue lengths count items. `maxGossipTopicConcurrency` caps concurrent jobs per topic. No byte accounting.                                                                                                                                                                   | Intentionally different: bytes are bounded from receipt through execution.                                                                                                                                                                     |
| Urgency and order             | Blocks, blob sidecars and data columns are urgent: claimed and started whatever the BLS and regen state and the binding pump's time budget. Other kinds are claimed while BLS and regen accept work (`executor.ready()`), in the order block, blob, column, aggregate, exit, BLS change, attestation, proposer slashing, attester slashing, contribution, sync message, light client updates. Attestations, aggregates, sync messages and contributions are taken newest first. Claims hold at most 64 messages and 16 MiB.                  | `bypassQueue` for blocks, execution payloads, blobs and columns; `checkAcceptWork` gates the rest. Same order and same newest-first kinds. At most 128 jobs per tick.                                                                                                        | Mirror (execution payloads are Gloas).                                                                                                                                                                                                         |
| Attestation grouping          | Grouped by AttestationData and fork digest. A group is ready at 32 members or 50 ms after its first member's admission, so after a dependency wait it can be claimed at once. The most recently ready group goes first. A job takes up to 64 members.                                                                                                                                                                                                                                                                                        | Indexed by AttestationData. A key is ready at 32 members or 50 ms after its first insertion into the queue, so after a dependency wait it waits another 50 ms. Size-ready keys go before age-ready ones. A job takes up to 128.                                              | Intentionally different: native ages a group from admission, orders ready groups by readiness alone and caps a job at the 64-message claim.                                                                                                    |
| Dependency waiting            | Only attestations and aggregates wait, on their `beacon_block_root`. Lodestar answers each check from fork choice and searches an unknown root (`executor.check`): at most 32 roots per slot, with up to 4 new roots per peer and 32 source peers per root. Searches accept slots from the current slot minus two through the next slot and expire with that window. An unknown root waits until its import, or until a recheck after more than 256 imports in one pump turn; a negative check that raced an import is retried. Waiting takes at most half of a kind's items, and one peer at most a quarter; beyond that the message gets an Ignore verdict (`dependency_full`). | Attestations and aggregates (and Gloas kinds) await block import by root: at most 16384 awaiting a block and 1024 awaiting a payload. Searches are tracked per slot and root, from up to 32 peers per root. A block's unknown parent is searched at receipt.                 | Intentionally different: memory is bounded by preallocated cells per kind and per peer, not by a global count. A block's unknown parent is searched by the block validator (`blockUnknownParent`), which runs at once since blocks are urgent. |
| Expiry and deadlines          | Each admitted message has a validation deadline 30 s after admission (`validationTimeoutMs`), when gossipsub expires its pending validation: the message is never forwarded and a later verdict is not applied. At the deadline the processor retires a message not yet delivered to the host; a delivered message keeps its cell and charges until the host completes.                                                                                                                                                                      | No deadline in queues: messages wait until drained or dropped. Awaiting messages expire 3 slots after their search slot. Dropped messages get no verdict and are never forwarded.                                                                                            | Intentionally different: an admitted message ends by a verdict or by protocol expiry at its validation deadline, and delivered work keeps its cell and charges until the host completes.                                                       |
| Slot eligibility              | Blocks, blobs and columns use `slot - 32` through `slot + 1`. Attestations and aggregates use the preceding slot for the coarse lower bound to retain clock-disparity grace: 32 slots before Deneb, or the start of the previous epoch from Deneb. Their upper bound is `slot + 1`; host validation applies exact time rules. Checked at receipt and again while queued, waiting or claimed.                                                                                                                                                 | The same lower bound at receipt; the upper bound comes with #10023 below.                                                                                                                                                                                                    | Intentionally different at admission: the slot-only prefilter leaves exact time validation to the host.                                                                                                                                        |
| Drop all                      | `dropQueued` gives an Ignore verdict, in bounded passes, to each message admitted before it that is queued, awaiting a dependency check or waiting. Work already delivered to the host runs to its verdict.                                                                                                                                                                                                                                                                                                                                  | `dropAllJobs` clears queued and awaiting messages; running validations continue.                                                                                                                                                                                             | Mirror.                                                                                                                                                                                                                                        |
