# Native gossip queue rules

With the native backend, the lodestar-z gossip processor (`src/network/gossip_processor/`) owns gossip queueing: admission, per-kind limits, credits, grouping, dependency waiting, deadlines and slot eligibility. Lodestar supplies the named per-kind limits (`gossipKindLimits` in `config.ts`), the dependency answers and the validators (`executor.ts`), which are the same functions `NetworkProcessor` (`../../processor/`) runs.

Each rule below sits next to its `NetworkProcessor` counterpart on unstable, with a decision: **mirror** (same rule), **equivalent** (same bound or outcome by another mechanism), **intentionally different**, or **unsupported** (Gloas, which native refuses at startup). Each `NetworkProcessor` semantics change on unstable adds a row to the second table when the branch rebases.

Reviewed against lodestar-z 39616cb2 and unstable at fbb58f7280; the branch base is 92b9ec6e8b.

## Rules

| Rule                          | Native                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | NetworkProcessor                                                                                                                                                                                                                                             | Decision                                                                                                                                                                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission and per-kind limits | Each kind has an item and a byte limit (`gossipKindLimits`). Bytes are 4 KiB pages, at least the kind's largest compressed message. One peer holds at most half of a kind's items and bytes. A message without room is refused at receipt: no verdict, no forwarding, no score effect.                                                                                                                                                                                                                                                        | One queue per topic type with a fixed length (blocks 1024, blobs and columns 4096, aggregates 5120, attestations 24576, others 1024 to 16384), counted in items.                                                                                             | Intentionally different: bytes are bounded and preallocated, limits are sized to a slot's traffic, and each peer has a share.                                                                                                                  |
| Drop order when full          | Attestations, aggregates, sync messages and contributions evict their oldest message with an Ignore verdict. Other kinds refuse the new message.                                                                                                                                                                                                                                                                                                                                                                                              | LIFO queues (aggregates, sync messages, contributions) and the attestation queue drop their oldest message; FIFO queues drop the newest.                                                                                                                     | Mirror.                                                                                                                                                                                                                                        |
| Byte and item credits         | Payload pages are charged per kind and per peer from capture to retirement. Host execution has separate per-kind item and byte credits, split from the host budget (4096 items and 64 MiB by default) by `executionItems` and `executionBytes`, and capped by `maxGossipTopicConcurrency` and the processor items.                                                                                                                                                                                                                            | Queue lengths count items. `maxGossipTopicConcurrency` caps concurrent jobs per topic. No byte accounting.                                                                                                                                                   | Intentionally different: bytes are bounded from receipt to verdict.                                                                                                                                                                            |
| Urgency and order             | Blocks, blob sidecars and data columns are urgent: claimed and started whatever the BLS and regen state and the drain's time budget. Other kinds are claimed while BLS and regen accept work (`executor.ready()`), in the order block, blob, column, aggregate, exit, BLS change, attestation, proposer slashing, attester slashing, contribution, sync message, light client updates. Attestations, aggregates, sync messages and contributions are taken newest first. Claims hold at most 64 messages and 16 MiB.                          | `bypassQueue` for blocks, execution payloads, blobs and columns; `checkAcceptWork` gates the rest. Same order and same newest-first kinds. At most 128 jobs per tick.                                                                                        | Mirror (execution payloads are Gloas).                                                                                                                                                                                                         |
| Attestation grouping          | Grouped by AttestationData and fork digest. A group is ready at 32 members or 50 ms after its first admission. A job takes up to 64 members.                                                                                                                                                                                                                                                                                                                                                                                                  | Indexed by AttestationData. A key is ready at 32 members or 50 ms. A job takes up to 128.                                                                                                                                                                    | Equivalent: jobs are capped by the 64-message claim.                                                                                                                                                                                           |
| Dependency waiting            | Only attestations and aggregates wait, on their `beacon_block_root`. Lodestar answers each check from fork choice and searches an unknown root (`executor.check`): at most 96 roots at once, each for 30 s, from up to 8 peers. An unknown root waits until its import, or until a recheck after more than 256 imports in one drain turn; a negative check that raced an import is retried. Waiting takes at most half of a kind's items, and one peer at most a quarter; beyond that the message gets an Ignore verdict (`dependency_full`). | Attestations and aggregates (and Gloas kinds) await block import by root: at most 16384 awaiting a block and 1024 awaiting a payload. Searches are tracked per slot and root, from up to 32 peers per root. A block's unknown parent is searched at receipt. | Intentionally different: memory is bounded by preallocated cells per kind and per peer, not by a global count. A block's unknown parent is searched by the block validator (`blockUnknownParent`), which runs at once since blocks are urgent. |
| Expiry and deadlines          | Each admitted message has a deadline 30 s after admission (`validationTimeoutMs`). Past it the processor drops the message, gossipsub's pending validation expires unforwarded, and a late verdict is not applied.                                                                                                                                                                                                                                                                                                                            | No deadline in queues: messages wait until drained or dropped. Awaiting messages expire 3 slots after their search slot. Dropped messages get no verdict and are never forwarded.                                                                            | Intentionally different: every admitted message retires by a verdict or its deadline, which returns its credits.                                                                                                                               |
| Slot eligibility              | Blocks, attestations, aggregates, blobs and columns must be at least at `slot - 32` (attestations from Deneb: the start of the previous epoch) and at most `slot + 1`. Checked at receipt, where an ineligible message is refused, then once per slot while queued or waiting and at claim, where it gets an Ignore verdict.                                                                                                                                                                                                                  | The same lower bound at receipt; the upper bound comes with #10023 below.                                                                                                                                                                                    | Mirror for the lower bound.                                                                                                                                                                                                                    |
| Drop all                      | `dropQueued` ignores every message admitted before it, in bounded passes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | `dropAllJobs` clears queued and awaiting messages.                                                                                                                                                                                                           | Mirror.                                                                                                                                                                                                                                        |
