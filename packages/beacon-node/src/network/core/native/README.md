# Native gossip queue rules

With the native backend, the lodestar-z gossip processor (`src/network/gossip_processor/`) owns gossip queueing: admission, per-kind limits, credits, grouping, dependency waiting, deadlines and slot eligibility. Native derives limits from beacon configuration and the active validator count. Lodestar supplies the dependency answers and the validators (`executor.ts`), which are the same functions `NetworkProcessor` (`../../processor/`) runs.

The owner derives its current slot from genesis time and the fork-aware slot durations. It updates fork and BPO subscriptions, long-lived subnets, committee expiry and peer demand without a JS timer. Lodestar supplies status, sparse absolute duties, custody count and subscription flags through `NativeIntent`; coalesced updates resolve when applied. Native skips directly to the current slot after a stall and never moves its applied slot backward. Protocol deadlines still use monotonic time. Status must include earliest-available slot from startup when Fulu is scheduled, so activation can proceed without another host update. An unsupported fork activation stops the native runtime.

Each rule below sits next to its `NetworkProcessor` counterpart on unstable, with a decision: **mirror** (same rule), **equivalent** (same bound or outcome by another mechanism), **intentionally different**, **not yet mirrored** (an open requirement), or **unsupported** (Gloas, which native refuses when active or requested). Each `NetworkProcessor` semantics change on unstable adds a row to the second table when the branch rebases.

The tables originated from a comparison of lodestar-z 39616cb2 and unstable fbb58f7280; the branch base is 92b9ec6e8b. They are a comparison inventory, not a claim of complete behavioral parity. The binding pump lives in lodestar-z's `bindings/src/network-pump.js`; native owns operation Promises, which it settles during each bounded exchange. `nativeNetworkCore.ts` supplies the host callbacks; asynchronous validation and serving retain their obligations until completion.

## Runtime configuration and failures

Select native networking with `--network.backend=native --tcp=false --quic=true`. It supports IPv4, IPv6, or both, with at most one QUIC listener and one discovery listener per family. Discovery can learn advertised endpoints; explicit endpoints remain fixed. The workspace catalog pins `@chainsafe/lodestar-z` to a Git commit because the network and LevelDB APIs are not yet published. Installing dependencies builds its mainnet binding from source and requires Zig 0.16.0, Rust/Cargo, and CMake.

The network keeps its wrapper and event loop alive until explicit close or environment termination. Connected-peer lists, counts and dumps use the latest delivered native observations; they can lag the owner while events await delivery. Identity is initialized once and updated by coalesced native observations. Retained peer scores and detailed gossip diagnostics are read on demand by the owner. Diagnostic pages collected across turns do not represent one instant in time. Metrics scrapes request an owner render and share concurrent requests. A scrape racing network shutdown omits native metrics.

When a peer store directory is configured, native loads and checkpoints up to 256 qualified peers in `native-remembered-peers.txt`. The line-oriented cache is scoped to the genesis validators root; peers expire after 24 hours. Invalid files give a cold start and malformed records are skipped. Native owns the five-minute checkpoint and final shutdown attempt. A single Zig I/O task writes independently of network progress. Shutdown joins that task outside the runtime mutex; a stalled filesystem can delay close or worker teardown beyond the network's graceful-close deadline.

`NativeIntent` keeps one submitted update and one pending batch. Pending Status, custody and core-topic values coalesce to the latest request; committee demands merge. Callers in the same pending batch share its completion, so a superseded intermediate value need not be applied. Failed batches leave the last acknowledged state unchanged. The adapter submits only one state command at a time, using admission reserved from unrelated commands, without a retry timer. Once an admitted command races shutdown, rejection is not proof that its effect was rolled back.

Building or publishing an exchange result while JavaScript remains runnable is part of the bridge contract: a failure there is process-fatal, not an operation-local `NetworkResultAllocationFailed` rejection. If the JavaScript environment has stopped, native teardown reclaims the outstanding obligations.

## Rules

Gossipsub also uses `gossipKindLimits` for compressed messages awaiting validation. Pending items, bytes and source shares stay charged until a verdict is applied or validation expires. Retained messages use a separate compressed history allowance until eviction or expiry. These allowances have different lifetimes from the decoded storage and host execution credits described below.

| Rule                          | Native                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | NetworkProcessor                                                                                                                                                                                                                                                             | Decision                                                                                                                                                                                                                                       |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admission and per-kind limits | Each kind has an item and a byte limit (derived by native `application_policy`). Bytes are 4 KiB pages, at least the kind's largest compressed message. One peer holds at most half of a kind's items, and about half of its bytes: the peer's byte share also counts inline storage and is never below the kind's largest message. A message without room is refused at receipt: no verdict, no forwarding, no score effect.                                                                                                                                                                                    | One queue per topic type with a fixed length (blocks 1024, blobs and columns 4096, aggregates 5120, attestations 24576, others 1024 to 16384), counted in items.                                                                                                             | Intentionally different: bytes are bounded and preallocated, limits are sized to a slot's traffic, and each peer has a share.                                                                                                                  |
| Drop order when full          | Attestations, aggregates, sync messages and contributions evict the oldest message of the kind that is queued, awaiting a dependency check or waiting, with an Ignore verdict. Other kinds refuse the new message.                                                                                                                                                                                                                                                                                                                                                                                               | LIFO queues (aggregates, sync messages, contributions) drop their oldest message and FIFO queues their newest. The attestation queue drops the first message of its oldest indexed group, which need not be the oldest message left; awaiting messages are not in the queue. | Mirror for the other kinds. Intentionally different for attestations: native evicts the oldest attestation it holds, including one waiting on a dependency.                                                                                    |
| Byte and item credits         | A message holds its kind's item count and its peer's share until retirement. Decoded payload pages are released on delivery. Host execution has separate per-kind item and byte credits, held from claim until the host's verdict and split from the host budget (4096 items and 64 MiB by default) by `executionItems` and `executionBytes`, capped by `maxGossipTopicConcurrency` and the processor items.                                                                                                                                                                                                     | Queue lengths count items. `maxGossipTopicConcurrency` caps concurrent jobs per topic. No byte accounting.                                                                                                                                                                   | Intentionally different: bytes are bounded from receipt through execution.                                                                                                                                                                     |
| Urgency and order             | Blocks, blob sidecars and data columns are urgent: claimed and started whatever the BLS and regen state. Other kinds are claimed while BLS and regen accept work (`executor.ready()`), in the order block, blob, column, aggregate, exit, BLS change, attestation, proposer slashing, attester slashing, contribution, sync message, light client updates. Attestations, aggregates, sync messages and contributions are taken newest first. Each exchange claims up to 64 messages with an 8 MiB target. The first message may exceed that target, up to the native 16 MiB ceiling.                             | `bypassQueue` for blocks, execution payloads, blobs and columns; `checkAcceptWork` gates the rest. Same order and same newest-first kinds. | Attestation grouping          | Grouped by AttestationData and fork digest. A group is ready at 32 members or 50 ms after its first member's admission, so after a dependency wait it can be claimed at once. The most recently ready group goes first. A job takes up to 64 members.                                                                                                                                                                                                                                                                                                                                                            | Indexed by AttestationData. A key is ready at 32 members or 50 ms after its first insertion into the queue, so after a dependency wait it waits another 50 ms. Size-ready keys go before age-ready ones. A job takes up to 128.                                              | Intentionally different: native ages a group from admission, orders ready groups by readiness alone and caps a job at the 64-message claim.                                                                                                    |
| Dependency waiting            | Only attestations and aggregates wait, on their `beacon_block_root`. Lodestar answers each check from fork choice and searches an unknown root (`executor.check`): at most 32 roots per slot, with up to 4 new roots per peer and 32 source peers per root. Searches accept slots from the current slot minus two through the next slot and expire with that window. An unknown root waits until its import; a negative check that raced an import is retried. Waiting takes at most half of a kind's items, and one peer at most a quarter; beyond that the message gets an Ignore verdict (`dependency_full`). | Attestations and aggregates (and Gloas kinds) await block import by root: at most 16384 awaiting a block and 1024 awaiting a payload. Searches are tracked per slot and root, from up to 32 peers per root. A block's unknown parent is searched at receipt.                 | Intentionally different: memory is bounded by preallocated cells per kind and per peer, not by a global count. A block's unknown parent is searched by the block validator (`blockUnknownParent`), which runs at once since blocks are urgent. |
| Expiry and deadlines          | Each admitted message has a validation deadline 30 s after admission (`validationTimeoutMs`), when gossipsub expires its pending validation: the message is never forwarded and a later verdict is not applied. At the deadline the processor retires a message not yet delivered to the host; a delivered message keeps its cell and charges until the host completes.                                                                                                                                                                                                                                          | No deadline in queues: messages wait until drained or dropped. Awaiting messages expire 3 slots after their search slot. Dropped messages get no verdict and are never forwarded.                                                                                            | Intentionally different: an admitted message ends by a verdict or by protocol expiry at its validation deadline, and delivered work keeps its cell and charges until the host completes.                                                       |
| Slot eligibility              | Blocks, blobs and columns use `slot - 32` through `slot + 1`. Attestations and aggregates use the preceding slot for the coarse lower bound to retain clock-disparity grace: 32 slots before Deneb, or the start of the previous epoch from Deneb. Their upper bound is `slot + 1`; host validation applies exact time rules. Checked at receipt and again while queued, waiting or claimed.                                                                                                                                                                                                                     | At receipt, uses `slot - 32` except for Deneb-and-later attestations, which use the start of the previous epoch. Aggregates still use `slot - 32`; neither gets the native grace slot. The upper bound comes with #10023 below.                                              | Intentionally different at admission: the slot-only prefilter leaves exact time validation to the host.                                                                                                                                        |
| Drop all                      | `dropQueued` gives an Ignore verdict, in bounded passes, to each message admitted before it that is queued, awaiting a dependency check or waiting. Work already delivered to the host runs to its verdict.                                                                                                                                                                                                                                                                                                                                                                                                      | `dropAllJobs` clears queued and awaiting messages; running validations continue.                                                                                                                                                                                             | Mirror.                                                                                                                                                                                                                                        |
